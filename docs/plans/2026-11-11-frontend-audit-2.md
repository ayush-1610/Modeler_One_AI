# Frontend audit 2 (2026-11-11): what is still weak after the twelve fixes, and the plan

Audit of the deployed `main` (64fedf4): every page measured at 1280 and 390 px with the published Dapagliflozin model's
values and a stub-engine campaign that escalated; eight reviewers by dimension; each finding re-checked by a skeptic
(70 kept, 5 refuted). Web unless an item says otherwise.

## The owner's decisions (2026-11-11)
1. **Escalation popup (item 4):** the dialog opens by itself only on the escalated campaign's own project and campaign
   pages; every other page shows a pill "N decisions waiting · Open". "Decide later" holds for the rest of the browser
   tab session.
2. **Run (item 6):** a campaign starts only from the MAP signed on Review & sign; the one-click prepare-sign-start on
   the Run page is removed, with one start button.
3. **Held values needing a unit (item 1):** the person types the value in PK-Sim's unit; the unit is chosen only from
   the PK-Sim units harvested for that parameter (CLAUDE.md: never invent units). Nothing is converted automatically.
4. **Where values are accepted:** per value, on Inputs (today's screens). The comment saying "nothing is accepted here,
   the one review is at the MAP signature" is stale and is corrected.

### 9. Resilience: honest liveness, polling that recovers, read timeouts, plain outage messages
- **Why:** After one good answer, the sidebar says 'live' while the API is down. If the first escalations read fails, polling never restarts, so the global popup and liveness never recover without a reload. This applies to every polled read. A hung API leaves pages on the skeleton for minutes (proxyTimeout 600 s for GETs too). Every outage shows 'Try fewer files at once' plus operator advice. A wrong campaign id polls forever and promises the campaign will appear. The GoF plot resets the person's zoom every 2.5 s while a run is in progress, which moves interactive content under the pointer, and it has no load-failure state. Content below the fold stays at opacity 0 in print and save-as-PDF, so a reviewer's printout loses sections. Merged from perf-errors (7 findings).
- **What:** useApiLive: test esc.problem first. useResource refetchInterval: keep polling on error with backoff capped at 30 s; expose dataUpdatedAt/isError. serverGet and GET request(): AbortSignal.timeout(env, default 30-60 s), mapped to one sentence; multipart uploads are exempt. failure(): add a method/upload flag, keep 'fewer files' only for uploads, and drop the MODELER_API_BASE hint from the browser. AutoRefresh: giveUpAfterMs (about 30 s for notFound, then 'No campaign with this id is recorded.'), backoff on API problems, skip while document.hidden. ConcentrationTimePlot: uirevision, a content-keyed memo, Plotly.purge on unmount, .catch → 'The plot could not be loaded'. lib/motion.ts: replace inline opacity with a .reveal-pending class plus @media print{opacity:1 !important}, add a beforeprint reveal, and clear the safety interval when nothing is pending.
- **Pages:** Global (Nav, popup, every client read), campaign page, every printed page · **Effort:** medium
