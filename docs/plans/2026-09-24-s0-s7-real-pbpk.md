# Plan: make Modeler One do real PBPK, S0 → S7, proven on published models

## Context — why this plan exists

You ran the tool and every campaign stopped at S1. You were right to be angry, and right on two counts:

1. **The last round of case studies was not PBPK.** The engine server was down, so they ran on a one-compartment
   stand-in. That is pharmacokinetics without the physiology — no organs, no tissue partitioning. It should never
   have been presented as a test of this tool.
2. **The pipeline only really runs S0 → S1 (S2 for an oral solution).** MS-01 defines eight stages. S3–S7 are
   unbuilt, stubbed, or silently skipped.

And a third problem you named: **there is no change log**, and the entry-point doc (`CONTINUATION_PACKAGE.md`) is
**50 commits out of date** — it still says "164 tests" and "not yet a git repo". Switch model or session and the
context is lost.

**Goal of this push (your decisions):** a campaign that runs **all of S0 → S7 on real PK-Sim**, producing a signed,
reproducible regulatory package — **proven by re-running published OSP models against their real clinical data**.
Renal clearance rule approved (marked UNVERIFIED). Engine on the **server, with Docker on the Mac as fallback**.
DDI / paediatric application templates are the *next* phase, not this one.

## Diagnosis — what is actually going on

### What is genuinely PBPK and already works (engine-verified on the server)
- CPF → PK-Sim snapshot builder: real physiology (4-compartment organ model, Rodgers & Rowland partitioning)
- IV and oral-solution simulation on real PK-Sim (241-point profiles)
- Parameter identification through ospsuite, including SD, CV and 95% CIs per estimate
- Engine tasks `simulate`, `pk_analysis`, `population`, `sensitivity`, `batch`, `parameter_identification`
- NCA, ICH M15 tiered acceptance, the diagnostics ruleset, the strategist
- MAR generator, reproducibility bundle and `rerun_all.R` (byte-exact re-run verified on the server)
- Builder support for **Weibull tablets** and **expression profiles** — present, engine-verified, never wired from the CPF

### Why every run stops at S1 — the roadblocks

| # | Roadblock | Root cause | Severity |
|---|---|---|---|
| R1 | **S4 and S5 never simulate anything** | `map._scenarios` only emits scenarios for INTERNAL studies in 3 classes (IV→S1, oral fasted→S2, fed→S3). No scenario is ever tagged S4; EXTERNAL studies are skipped with `continue`. | **Critical — the reason** |
| R2 | The runner has no validation mode | Every stage is treated as a fit loop. MS-01 S4/S5 are "simulate once from the *final* CPF, judge, never fit". | Critical |
| R3 | Multiple-dose, modified-release, special-population studies are never used | Those study classes map to no stage at all. | High |
| R4 | **Enzyme-cleared drugs are not metabolised on real PK-Sim** | The CPF build never attaches expression profiles to the individual, so CYP/UGT processes have no enzyme to act on. Affects most drugs. | **Critical** |
| R5 | Tablets and capsules can't be simulated; S3 doesn't exist | Round builder only places solution/suspension; Weibull is never wired from the CPF; no formulation sub-loop. Most oral drugs are tablets. | High |
| R6 | Renally cleared drugs can't be fitted on clearance | Clearance rule offers only hepatic clearance and logP. *(Approved: add renal branch.)* | High |
| R7 | No VPC / population check | MS-01's S1 gate requires ≥80% of observed points inside a 100-person 5–95% band. Engine task exists; not in evaluation. | High |
| R8 | **S6 (prediction) is not in the pipeline** | Sensitivity task exists but is never called; uncertainty propagation not built. | High |
| R9 | **S7 (report & package) is not in the pipeline** | MAR, M15 table, bundle and re-run exist as libraries; campaign completion never produces them. No pandoc anywhere → no DOCX/PDF-A. | High |
| R10 | Engine availability | Server: drops off LAN, no Tailscale, root disk **95% full (100 GB left)**, running an old build. Mac Docker installed but never used. | High |
| R11 | Last case studies weren't PBPK | Ran on the analytical stand-in. | High |
| R12 | Documentation debt | No change log; continuation doc 50 commits stale. | High |
| R13 | A successful fit isn't credited until the next round | Round evaluates the *pre-fit* simulation, wasting round budget. | Medium |

### The asset that changes everything
The OSP reference models already in the repo (`services/engine-worker/golden/fixtures/`) contain **362 real clinical
datasets**: Dapagliflozin 55 · Itraconazole 103 · Midazolam 115 · Rifampicin 89 — with real tablet formulations and
real clearance processes. These are peer-reviewed, qualified PBPK models. They are the honest ground truth this tool
has been missing.

## The plan

Five phases, in dependency order. Each ends with a concrete, checkable exit criterion and a change-log entry.

### Phase 0 — Foundation (unblocks everything)

**0.1 Change documentation — first, and permanent**
- New `CHANGELOG.md` at the repo root: dated entries — *what changed, why, which commit* — backfilled for the
  50 undocumented commits.
- New `CLAUDE.md` at the repo root. Claude Code loads it into **every** session automatically, so this is what makes
  the rule survive a model or session switch: *read `docs/CONTINUATION_PACKAGE.md` first; every behaviour change adds
  a `CHANGELOG.md` entry in the same commit; update the pipeline-coverage table when a stage changes.*
- Rewrite `docs/CONTINUATION_PACKAGE.md` §4 to the truth, with a **pipeline-coverage table** (S0–S7:
  done / partial / missing) that each phase below updates.
- Exit: a fresh session reading only `CLAUDE.md` → `CONTINUATION_PACKAGE.md` → `CHANGELOG.md` knows exactly where
  things stand.

**0.2 Server — reliable while it is up now**
- Tailscale via the existing `deploy/server/setup_tailscale.sh` over ssh (you open one login link).
- Deploy the current build (sync, `uv sync`, web build, `install_autostart.sh`).
- Engine outputs under `~/modeler-data` with a retention policy; report the 95% root disk to you (not ours to delete).
- Exit: `golden_roundtrip.R` + `verify_run_round.sh` pass on the server, reachable over its Tailscale address.

**0.3 Mac Docker fallback**
- Build `services/engine-worker/Dockerfile` (linux/amd64) in Docker Desktop; run the golden scripts inside.
- `deploy/dev/docker_engine.sh <job.json>` — mounts the job's working dir at the same path so `EngineRunner` works
  unchanged as `MODELER_ENGINE_COMMAND`.
- **Retire the analytical stand-in from every demo and case-study path.** It stays only as a unit-test fixture.
- Exit: the same golden scripts pass on the Mac container.

### Phase 1 — Complete the modelling loop S0 → S5 on real PBPK

**1.1 Validation stages S4 / S5** (R1, R2, R3)
- `packages/pbpk-domain/src/pbpk_domain/campaign/map.py` `_scenarios`: also emit an **S4** scenario for every INTERNAL
  study and an **S5** scenario for every EXTERNAL study, including multiple-dose / MR / special-population classes
  (MS-01 §3.3 rule 4). The signed MAP then records exactly what gets validated.
- Runner validation mode — `services/orchestrator/.../local_runner.py` `_run_stage` (and `StageLoopWorkflow` for
  parity): for S4/S5 one round, simulate from the carried-forward **final** CPF, evaluate, **never** diagnose or fit.
  S5 failure escalates with MS-01 §6.6 options.
- `packages/pbpk-domain/src/pbpk_domain/acceptance.py`: add a grouping dimension so S5 judges **fasted and fed as
  separate groups** (MS-01 §8). Reuses the existing `(role, quantity)` grouping.

**1.2 Expression profiles** (R4)
- `packages/pbpk-domain/src/pbpk_domain/cpf/build.py`: for each molecule-based process, attach an
  `ExpressionProfileSpec` (builder.py:455) to every subject via its existing `expression` field (builder.py:510).
  Enzyme / Transporter / OtherProtein by process kind; PK-Sim database defaults unless the CPF carries a reference
  concentration.
- Exit: a CYP-cleared CPF actually eliminates on the server — asserted, not assumed.

**1.3 Tablets, capsules and S3** (R5)
- CPF parameters `form.{name}.weibull.{t50,shape,lag}` (MS-01 §2.2) → `WeibullFormulationSpec` (builder.py:610) in
  `campaign/round_build.py`; lift the solution-only restriction.
- **Harvest** the Weibull parameter paths from the engine into `pksim_paths.py` — never invented (project rule).
- S3 formulation sub-loop: in-vivo Weibull adjustment within ±2× (MS-01 §4 S3); fed sub-loop with the meal templates
  already supported.

**1.4 Renal clearance rule** (R6, approved)
- `rulesets/diag_rules.yaml`: clearance rule gains `fit elim.renal.gfr_fraction` and `fit elim.renal.ts_clspec`;
  version bump; stays **UNVERIFIED**. The per-compound candidate filter already drops what doesn't apply.

**1.5 VPC** (R7)
- `population` engine task: n = 100 from each study's demographics, seed recorded → 5th/95th band → coverage of
  observed points, gated at ≥80% per MS-01 S1/S2. Band drawn on the goodness-of-fit plot.

**1.6 Credit a fit in the round it happens** (R13)
- After applying fitted estimates, re-simulate before evaluating.

Exit for Phase 1: a campaign runs S0 → S5 on real PK-Sim with internal and external validation reported separately.

### Phase 2 — S6 prediction and S7 regulatory package (R8, R9)

- Add **S6** and **S7** to `CAMPAIGN_STAGES` (`packages/run-contracts/.../runs.py`) as non-loop stages.
- **S6 sensitivity:** `sensitivity` task on every FITTED/PREDICTED parameter plus the EMA worst-case set.
- **S6 uncertainty:** sample fitted parameters from `run_pi.R`'s CIs (n = 200) → `batch` task → prediction intervals
  on the question's metric.
- **S7 package:** on completion — `assemble_mar` (report/mar.py:330) from the real evidence → `render_all`
  (DOCX + PDF/A; install pandoc as a static binary, no sudo) → M15 table → `assemble_bundle` + `generate_rerun_script`
  (reproducibility.py) → re-run on the engine → `verify_reproduction`. **Export is blocked unless reproduction passes**
  (decision D13).
- API: list and download campaign artifacts.

Exit: a completed campaign yields a MAR (DOCX + PDF/A) and a bundle whose re-run matches.

### Phase 3 — UI for the whole pipeline
- Monitor shows S0–S7; internal vs external validation, fasted vs fed; VPC band on the plot; sensitivity ranking;
  prediction interval; package download. Keeps the current design system and fold-error gauge.

### Phase 4 — Prove it on real published models, on real PK-Sim (R11)
- **Reference importer:** OSP snapshot → CPF (compound parameters + processes with engine bindings) + studies (from its
  `ObservedData`: times, values, units, LLOQ) + protocols/formulations (from its simulations).
- Two tests per model:
  1. **Round-trip:** from the published parameters, our builder reproduces OSP's own simulation outputs to 1e-6
     (T-10's original acceptance criterion).
  2. **Full campaign:** run S0 → S7 against the real clinical data; our fitted model's GMFE is at least as good as the
     published model's on the same studies.
- **Dapagliflozin** first (IV + oral + Weibull tablet, first-order metabolism + GFR — fully within reach after
  Phase 1), then **Rifampicin** (MM metabolism, transport, induction, GFR — all builder-supported).
- Re-publish the case-study report with **real** numbers, replacing the stand-in results.

Exit: both models complete S0 → S7 on real PK-Sim with results you can hold against the published models.
