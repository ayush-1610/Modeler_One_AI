# P0–P5 redesign: four steps, one review (R1, 2026-10-18)

Status: **approved by the owner on 2026-10-18.** All six screens were approved, with notes (§9). The notes are folded
into this document and the wireframes (https://claude.ai/artifact/W2KVB3PKunu5ru5MpJrM89, a private page). R0, the
run-integrity fixes, is PR #67 (`docs/plans/2026-10-18-run-integrity.md`).

## 1. Why
On 2026-10-15 the owner ran the tool on real data. P0–P5 was "near to impossible" to get through:
- data is entered at five different phases;
- every value and dataset asks for Accept / Reject with a reason (about 75–90 reasoned decisions on the real project);
- P3 Client data alone took about 70–110 actions across 12 workbooks;
- the agents are weak;
- the screens are dull and hard to scan.

Reading the code (2026-10-15) explained much of it:
- about 60 brief fields exist, but only 5 reach the model, the MAP or the report;
- the P2 and P3 approvals gate nothing;
- observed data has three ways in;
- P3 cannot capture a multiple-dose regimen or demographics, which the model needs.

The owner then marked all 104 rows of the P0–P5 field map (2026-10-17). The result: 51 keep, 16 drop, 14 move,
12 merge, 6 add, and 5 agree with the proposed flow. On 2026-10-18 the owner answered the open questions. This
document turns those decisions into screens. The map row ids (`p2-accept`, `m-md`, …) are cited so each decision can
be traced.

## 2. Decisions recorded here
| Id | Decision | Source |
|---|---|---|
| **D-27** | **Agents and code fill; a person reviews everything once, at the MAP signature.** There is no per-item Accept / Reject and no phase approval. This replaces rule 2 of §14.1 of `2026-09-25-project-startup-pipeline.md` ("agents never write records: they create proposals that people accept, edit or reject"). Rules 1 and 3–8 stand: code computes every regulatory number, every extracted value cites a verbatim span checked by code, and conflicts are never averaged | Owner, 2026-10-15; map row `b-review-model` |
| **D-28** | **Out-of-scope products are refused at Start**, before any data work. The person is asked for modality, model type, site of action and formulation type, and anything the builder cannot model gets "not supported yet". Today the builder makes full (whole-body) PBPK models of systemic small molecules with dissolved, Weibull and particle formulations; a minimal PBPK model is refused (the owner's note, 2026-10-18). Support is added one product type at a time, with the SME | Owner, 2026-10-18 |
| **D-29** | **Demographics are never silently defaulted.** For each study the person enters them, or chooses "healthy adult default". That is the OSP reference individual, `DEFAULT_DEMOGRAPHICS` in `pbpk_domain.campaign.split`: European (ICRP 2002), male, 30 years. The choice is a MAP limitation and appears in the MAR | Owner, 2026-10-18; map row `m-demo` |
| **D-30** | **SME thresholds are advisory until the SME signs**: identifiability, data quality, and acceptance per regulatory pathway. They are shown, recorded as provisional, and do not block. They become blocking once signed (T-30) | Owner, 2026-10-18 |
| **D-31** | **No per-stage time overrides.** Each stage gets its MS-01 share of the campaign budget signed in the MAP (S0 1 %, S1 20 %, S2 20 %, S3 7 %, SJ 15 %, S4 5 %, S5 5 %, S6 20 %, S7 7 %; with a metabolite stage SM takes 10 % and the rest scale by 0.9). A campaign that needs more time gets a larger budget in the plan, signed again. Enforced in R0: outside development a start that sets per-stage budgets is refused | Owner's screen note, 2026-10-18 ("keep the guardrails strict") |
| **D-32** | **Which value a model input takes.** Values within **10 %** after unit conversion agree and are one value with all its sources. Within **2-fold**, the best source wins: the client, then the literature by grade A–D, then PubChem, then the published model; the others are listed as alternatives for the review. Beyond 2-fold, a person keeps one. Nothing is averaged. A provisional data rule, UNVERIFIED for the SME, version 0.1 (`modeler_project/source_selection.yaml`) | Owner, 2026-10-18 (R3 plan) |
| **D-33** | **Blinding follows the proposed role.** A study the MS-01 split proposes for S5 (or S6) is blinded from the moment it is read, before any plan exists | Owner, 2026-10-18 (R3 plan) |

**How D-27 keeps the record sound:**
- Every value still carries who or what supplied it: the agent run with its model and prompt version, or the person,
  or the client file and cell. The audit trail records every change automatically.
- The review screen (Step 3) shows **every** value with its source, quote, grade and flags. A signature over values
  the signer cannot see would mean nothing.
- The signed MAP lists every CPF parameter with its value and source (`MapDocument.cpf_parameters`), so the Part 11
  signature covers them.
- The person can still exclude any value or study, with a reason (map `m-exclude`). Excluded is the only state a
  person sets by hand; the rest flows through.

## 3. The flow
| Step | Replaces | The person | The system |
|---|---|---|---|
| **1 · Start** | P0 + P1 | Names the drug, drops the proposal and any client files in one upload, and confirms the short brief | Identity from PubChem; A1 fills the brief with quotes; the scope gates (D-28); the data checklist |
| **2 · Inputs** | P2 + P3 + P4 | Fills only what the system could not, and picks a value only where sources truly disagree | One workspace with five tabs (Compound, Formulations, Individuals, Simulation settings, Studies). The agents run in the background, and a live "still missing to run" list |
| **3 · Review & sign** | P5 | The one full review, then Approve and Sign | Proposes study roles (MS-01 split) and fit bounds; the live validator |
| **4 · Run** | P6 | Watches, and decides escalations in the pop-up | S0–S7 unchanged |

The phase rail becomes a four-step stepper. Each step shows "done", "needs you" or "not started", computed from what
is filled and what is missing, not from approvals.

### 3.1 Step 1 · Start (P0 + P1)
**One screen, three blocks.**
1. **The drug and the files.**
   - Drug name (`p0-drug`): one field, which also fills the project name and title (`p0-name`, `p1-drugname`).
   - Context (`p0-context`).
   - One upload for the proposal, its annexes and the client's data files (`p0-files`, `p3-upload`). Client files go
     straight to Step 2.
   - PubChem identity: CID, SMILES, InChIKey and **one** molecular weight, used by both the model and unit conversion
     (`p1-pubchem`, `p1-mw`).
2. **The short brief**, filled by A1 (`p1-extract`). Every value shows its highlighted quote in the document viewer
   (`p1-viewer`). The person edits only what is wrong; no "why" is asked (`p1-why` dropped, the audit records it).
   - Question of interest, context of use, applications (APP codes) (`p1-qoi`, `p1-cou`, `p1-apps`).
   - **Model risk (required).** Model influence and decision consequence suggest the tier, as ICH M15 does; the
     person confirms it, with the reasons recorded (`p1-risk`, `p1-m15`). This is the value R0 made required, so the
     plan reads it from here.
   - **Scope gates (D-28).** Modality (`p1-modality`), model type (full PBPK; minimal PBPK is "not supported yet"),
     site of action (systemic / local), and formulation type, each with "not supported yet" for what the builder
     cannot model. BCS class (`p1-bcs`).
   - Route and food state of the scenarios (`p1-scen-route`).
   - Pathways, nonlinearity and enterohepatic recycling (`p1-scope`), with pathways as a multi-select. Which
     parameters S1–S3 may fit is SME content (`diag_rules.yaml`, locked); the multi-select only shapes the data
     checklist and the review.
   - Open questions (`p1-questions`).
   - **Proposal notes**, collapsed and optional, hold everything else the proposal says: title, project type, client
     and agencies, milestones, drug synonyms and salt form, product details, scenario doses, analytes, platform
     (`p1-title`, `p1-type`, `p1-admin`, `p1-drugother`, `p1-prodother`, `p1-scen-dose`, `p1-scope-other`). They
     are kept for the report and are never required.
3. **The data checklist**, derived (`p1-derive`) and shown as a list with no approval (`p1-dataplan-rows`,
   `p1-approve-plan` dropped):
   - each item shows its provider (client, literature, predict…) and an optional literature cross-check
     (`p1-provider`, `p1-crosscheck`);
   - it also lists what the client is expected to send, ticked off as their files arrive (`p3-expected`, `p3-stops`);
   - feasibility warnings sit inline on the item they concern (`p1-feasibility`);
   - the PK-Sim columns stay hidden (`p1-pksim-cols` dropped).

**Moved elsewhere:**
- products → Step 2 Formulations (`p1-products`);
- populations, regimens and intervals of prediction scenarios → applications in Step 3 (`p1-scen-other`,
  `p1-pops`);
- assumptions, exclusions and risks → Step 3 as MAP limitations (`p1-assump`).

**Hands to Step 2:** the drug identity, the scope, the checklist, and the client files.

### 3.2 Step 2 · Inputs (P2 + P3 + P4)
**One workspace, five tabs, a side list "Still missing to run".** That list is the readiness check, live
(`p4-readiness`). The CPF is assembled continuously (`p4-assemble`), not on a button.

**Compound tab** (`p4-tabs`): one row per model input, with value, unit, source(s), grade and flags.
- **Sources and agents.**
  - Every row is filled from the best source: the client, then the literature, then PubChem, then the published OSP
    model.
  - The literature agent (A2) runs in the background (`p2-search`). Its values land in the rows, with grade A–D,
    flags and the quote (`p2-grade`); a manual value is typed into the row itself (`p2-add`).
  - Alternatives sit under the row (`p2-other`).
  - A row can be marked "not available" with a reason (`p2-notavail`), and papers the agent could not read can be
    uploaded (`p2-access`).
- **Several sources agree (the owner's note on `p4-conflict`).** Values for the same parameter that agree after unit
  conversion become one value with all its sources listed, and the agreement raises its confidence. The agreement
  tolerance is a data rule: it ships provisional, marked UNVERIFIED for the SME (§6).
- **Sources disagree:** today, beyond 2-fold (`modeler_project.evidence.flag_conflicts`). The person keeps one,
  because values are never averaged (`p4-conflict`), and the others stay on record as rejected.
- **In-row fixes:**
  - corrections to a value's target, number or unit (`p4-correct`);
  - pKa acid or base (`p4-pka`);
  - which PK-Sim process carries a value (`p4-process`);
  - proposals for missing inputs, such as MW from PubChem or "ask the literature" (`p4-missing`).
- **More than one compound** (a parent with metabolites): the system panel lists the compounds and their formation,
  and each compound has its own rows. The campaign over the system starts in Step 3 (`m-system`).

**Formulations tab:**
- the products from the proposal (`p1-products`), and the formulation chosen for each solid study (`p4-formulation-choice`);
- dissolution facts, the Weibull fit with "propose as release model", and the f2 table (`p3-diss`, `p3-weibull`,
  `p3-f2`).

**Individuals tab** (the PK-Sim Individual building block; the owner's note):
- **Each study's individual.** The population database (a PK-Sim population such as `European_ICRP_2002`), sex, age,
  and the study's age range for its VPC population, with mean weight and height when reported (written to the
  individual's origin data; `pbpk_domain.campaign.split.Demographics`). Or the explicit "healthy adult default"
  (`DEFAULT_DEMOGRAPHICS`, D-29). A study whose published simulation names its own individual keeps it
  (`PublishedIndividual`).
- **Values the CPF places on the individual:** individual overrides at harvested Individual paths (`indiv.*`), and
  enzyme and transporter expression (`expr.*`, published expression profiles kept verbatim).

**Simulation settings tab:**
- **Calculation methods** (the model structure): partition coefficients and cellular permeability
  (`dist.partition_method`, `dist.permeability_method`). These are engine-exact names, checked against the harvested
  catalog. They are inherited from the published model when the compound comes from one, otherwise PK-Sim's defaults
  apply. S1 may try the alternative partition method as an MS-01 branch (the as-is reference run shows
  `branch dist.partition_method`). There is no Model Structure tab yet; the decision tree (guide item 2.1) stays
  deferred.
- **Values set on the simulation**, scoped to a route where needed (`sim[oral|iv].*`).
- **Solver settings** per study: those its published simulation sets (`StudyRecord.solver`, e.g. RelTol), else
  PK-Sim's defaults. Each study is simulated over its whole sampled window.
- **Not here:** prediction regimens (e.g. 10 mg twice daily). They are applications, in Step 3.

**Studies tab: one way in for observed data** (`p3-intake` dropped):
- **Client sheets.** Files are sorted automatically by the sheet agent (A4) and code (`p3-sort-agent`); the
  11-category screen is gone (`p3-triage`).
  - A reading agent proposes each sheet's reading: layout, rows, columns, units, statistic, LLOQ, SD, N, below-LLOQ
    text, and the study's facts (`p3-layout`, `p3-units`, `p3-study`).
  - The person corrects only what it got wrong and saves once, with problems shown inline (`p3-check`). The reading
    recipe is kept as the record but not shown (`p3-recipe`).
  - **When the agent cannot read a sheet, the fallback is in plain sight** (the owner's note): download the
    client-data template, which is read cell by cell with no AI (`p3-template`), or type the table in by hand: times,
    values, units, the study's facts, and the source. The manual path exists in the API today
    (`POST /projects/{id}/datasets`); the Studies tab gives it a visible form.
- **Literature tables and figures.** The table agent (A3) works as before (`p2-find-obs`), and so does the calibrated
  figure digitizer (`p2-digitize`). The digitizer must also read **figures that are images inside a PDF** (the
  owner's note), with zoom and crop to the figure, and a list of a PDF's figures.
- **New on each study:**
  - a multiple-dose regimen: number of doses and interval (`m-md`); the build already takes `n_doses` and the
    interval;
  - demographics, or the explicit "healthy adult default" (`m-demo`, D-29);
  - the study's role, **proposed here** from the MS-01 split and shown read-only: calibration (S1–S3), internal
    validation (S4), external validation (S5), application (S6) or supportive.
- **Roles change in Step 3 only**, on the stage canvas with a reason. **Blinding follows the S5 role:** a study in S5
  is blinded until the MAP is signed, and a reveal before that needs a reason (`p2-reveal`, D-15). Moving a study out
  of S5 is a role change with its reason, recorded like a reveal.
- No dataset is accepted one by one (`p2-dataset-accept`, `p4-datasets` dropped).

**Hands to Step 3:** the CPF, the formulations and the study catalog, with nothing on "still missing".

### 3.3 Step 3 · Review & sign (P5)
The current plan canvas (`p5-*`, all kept), around one new review table.
- **The review table.** Every input with value, unit, source(s), quote, grade, flags, who or what supplied it, and its
  confidence (display only, from grade, flags and agreement). Rows can be filtered: "flagged", "changed by a
  person", "from an agent". Any row or study can be excluded with a reason (`m-exclude`).
- **Studies and roles: the PBPK canvas stays** (the owner asked):
  - the Overall Data chips and the D3 stage canvas, the flow of studies into stages, dragged with a reason
    (`p5-studies`, `p5-canvas`);
  - the D1 disposition and D2 absorption diagrams, with the food-effect switch (`p5-d1`, `p5-d2`);
  - "the study is for" from P3 now lives here (`p3-purpose`): the role set here decides blinding (S5).
- **The estimation plan**, one table: each parameter fixed or estimated, its source, and its bounds.
  - Bounds are **proposed** (`m-bounds`): from the registry's physical bounds (`parameters/registry.yaml`
    `physical_bounds`), narrowed around the start value.
  - The proposal method is provisional, for the SME (§6).
  - It is the fit form as a table (`p5-fit`).
- **The validation plan:** which studies validate (S4 internal, S5 external, blinded), which criteria apply, and what
  happens if validation fails. All of it is in the MAP already; it gets its own section. The criteria are marked
  **provisional (SME)** because they are the UNVERIFIED rulesets.
- **Acceptance criteria for the risk tier** (the owner's note): the limits every round is judged by at the chosen tier
  (`MapAcceptance.criteria`, from the locked ruleset, provisional for the SME).
  - The person may set a **stricter project target only**: the brief already has it
    (`acceptance.internal_target_pe`, MS-01 §8), and the validator refuses a target looser than the tier.
  - Today nothing reads that field. Making verdicts apply it changes the locked MAP and acceptance code, so it goes in
    its own PR with the owner's approval, in R4.
- **VBE, its own panel** (`m-vbe`; the owner's note). The inputs of the `vbe-crossover` template:
  - the TEST and reference (RLD) formulations;
  - intra-subject variability: parameter, CV and source, never defaulted;
  - subjects per trial × number of trials;
  - the seed;
  - the probability-of-success threshold;
  - the optional observed BE study, for the F-304 gate; without it the result is "not validated";
  - the limits: 80–125 % on the 90 % CI by default; 90–111.11 % for a narrow therapeutic index, [VERIFY].
- **Other applications:** the populations and regimens of prediction scenarios moved from P1, e.g. 10 mg twice daily.
  Applications the campaign cannot run yet (DDI, paediatric, S3 fed) say **"not supported yet" here**, instead of a
  note at run time.
- **Credibility (ICH M15):**
  - the risk and its reasons from Step 1, editable here (the R0 control);
  - the campaign time budget (R0, default 8 h), with **the fixed per-stage split** shown in minutes for that budget
    (D-31). There are no per-stage overrides: more time means a larger budget, signed again;
  - the limitations: the assumptions moved from P1 (`p1-assump`), each "healthy adult default", and the split's own.
- The live validator, A5's draft and the diff from the MS-01 default stay as they are (`p5-validator`, `p5-a5`,
  `p5-diff`).
- **Approve and Sign** (Part 11, step-up) (`p5-sign`). Signing is the one review D-27 relies on.

### 3.4 Step 4 · Run (P6)
- Unchanged: S0–S7 and the monitor (`p5-run`).
- Escalations open as a dialog on the project and campaign pages (R0, `b-run`), and the review inbox stays as the
  list.

## 4. The agents in the new flow
- **A1, brief:** it fills the short brief only, every value quoted. It no longer fills the proposal notes field by
  field; they are kept as quoted text.
- **A2, literature.** It runs in the background, and code rules stop the misfilings seen on the real project:
  - a "% bound" value is converted by code (fu = 1 − bound / 100), never filed as fu;
  - fe (fraction excreted unchanged) is filed under its own id, never as the GFR fraction;
  - a value span that is not a number is refused.
- **Reading agent (new, replaces the regex guess in `sheet_form.py`):** it proposes each sheet's reading. Code checks
  every proposed cell against the sheet, and the person corrects.
- **The mapping agent,** built but wired to nothing today, maps sheet columns to CPF ids and study fields, checked by
  code.
- **Evaluation sets (T-21):**
  - Dapagliflozin, with the T-56 kit's known values and datasets;
  - the owner's real project, once its files are shared.

  Each agent is scored before and after each change.
- **The model stays the in-house one** (D-16). Whether a larger model is needed is decided from the evaluation scores,
  not before.

## 6. For the SME and the owner (open, not decided here)
1. **Agreement tolerance** for multi-source values.
   - Proposed: the same value after unit conversion, to within 10 %.
   - Provisional and UNVERIFIED, with its own version, like the rulesets.
2. **The proposal method for fit bounds:** the registry's physical bounds, narrowed to 0.1–10× the start value on a log
   scale. Provisional.
3. **The 1-hour goal and MS-01's time split.** S3's 7 % of 1 h is under a fit's 15-min reserve (R0 known gap).
4. **The regulatory pathway → acceptance criteria mapping**, which is ruleset content.
   **The influence × consequence → risk tier suggestion** in Step 1 is the same kind of content: it ships as a
   suggestion the person confirms, provisional until the SME signs.
5. **The thresholds of D-30:** identifiability, data quality and virtual population.
6. **Product calls:** MMF packaging, the structural revision loop, the version-tag format.
