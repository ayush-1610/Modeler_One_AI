# API to Page Mapping (Phase 7, Gate 4)

Every page and important action of the approved design, mapped to the API that exists today:
**Page → Component → User action → Backend service → API endpoint → Data model → Permissions → Expected result.**

**How it was made (2026-11-23).** The endpoint list is the published contract `docs/api/openapi.json` (183
operations). For every operation the handler was found by its operation id and its source read: the role dependency in
its signature (`Reader`, `Writer`, `MiddLead`, `Admin`, `require_role`), project scoping (`workspace_for`,
`require_project`), the owner-only guard (`ownership.owner_guard` on the routers `main.py` includes with
`OWNER_ONLY_WRITES`, or a direct `ensure_owner`), and the step-up (`ensure_step_up`, `sign_after_step_up`), one
level of helpers deep. Request and response models are the contract's schema names. A script refused any page action
whose endpoint is not in the contract, so nothing here is invented. Appendix A lists all 183 operations.

Classes: **1** fully supported · **2** partially supported · **3** backend-supported, exposed by this design · **4**
needs an API or backend change · **5** entirely new functionality · **6** frontend-only.

**Correction to Gates 1 and 2:** **25** operations had no screen, not 21 or 22 (the owner's count at Gate 1 was right). A
path-only text match had counted three as used because a GET shares their path: `POST /projects`,
`PUT /projects/{id}/compounds/{compound}/cpf` and `POST /projects/{id}/studies`. Scripts and tests call them;
the web app never does. Of the 25, the design puts 8 on a page and keeps 17 off (§3).

Permissions across the 183 operations (from the code): curator, reviewer 94, viewer, curator, reviewer 55, modeler-admin 23, any signed-in 5, header/password verifier 2, NONE (no sign-in) 2, reviewer 2;
**94** writes are owner-only (a reviewer the project is shared with may still sign the MAP and records);
**20** require a fresh step-up; every route with a `{project_id}` checks project membership.

## 4. What this means for implementation
- **Works today, unchanged (class 1):** 81 of 100 actions. The redesign changes their presentation, not their calls.
- **Exposed, no backend change (class 3):** the read-only plan, "Back to the MS-01 default", "What this changes", the
  campaign package, an agent run's turns, the data plan.
- **Partial (class 2):** Home, Your work and Projects read step state once per project (R-N03); the project's open-item
  counts are computed in the browser as Inputs does today; History's signatures are filtered from the audit chain
  (R-N09); the escalation flash still reaches members who may not sign (R-S02); raw run results and engine status wait
  for the multi-server deployment or a new check (R-N08).
- **Needs a change (class 4), new (class 5):** the agent-run list (R-N05), the platform audit log (R-N07), live status
  (R-N06). Details in [`BACKEND_CHANGE_REQUIREMENTS.md`](BACKEND_CHANGE_REQUIREMENTS.md).
